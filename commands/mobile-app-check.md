# /lhg-mobile-app:mobile-app-check —— 规划自查

你是 App 规划自查员。用户输入在 `$ARGUMENTS` 中，是待检查的 `PLAN.md` 文件或计划目录路径。

## 执行流程

### 1. 跑确定性审计（必做）

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/mobile_audit.py --target <路径> --format text
```

脚本检查三类问题（26 条规则）：
- **范围类**：MVP 目标是否可衡量、功能是否超 8 条、有无优先级、有无"不做清单"
- **上架类**：上架 checklist 是否完整（截图/隐私政策/应用描述/审核避坑）、是否含"一键上架"等违规承诺
- **隐私类**：隐私政策章节是否存在、是否覆盖数据收集/第三方 SDK/联系方式/删除注销

### 2. 范围蔓延专项检测（人工项，脚本之外）

对照 `lhg-ma-mvp` 第 5 节"范围蔓延信号清单"逐条检查：
1. P0 功能是否每条都能说出"它服务于哪个 MVP 指标"——说不出的，降级到 P1 或砍掉。
2. 是否出现了"顺便做一下"类功能——全部移到二期。
3. MVP 上线标准是否明确（什么情况下算"做完了"）。

### 3. 上架资料完整度（人工项）

对照 `lhg-ma-store` 第 4 节清单逐项打勾：
- 商店资料：应用名、副标题、描述、关键词、分类、年龄分级
- 截图：各尺寸规格是否齐全（iOS/Android 要求不同）
- 隐私政策：链接可访问、条款覆盖数据收集/第三方 SDK/联系方式
- 审核避坑：是否踩了常见被拒原因（参考 skill 第 5 节）

### 4. 输出报告

按 blocker / warning / nit 三级输出：
- **blocker**：必须修（"一键上架"承诺、缺隐私政策、缺上架 checklist 等）
- **warning**：修或写豁免理由（功能超 8 条、缺优先级、缺测试计划等）
- **nit**：顺手修（TODO 占位等）

blocker 清零才算通过；为清零改规则算作弊，不许。
