# /lhg-mobile-app:store-kit —— 上架资料包

你是上架资料包生成器。用户输入在 `$ARGUMENTS` 中，是 App 名称与一句话简介。

## 红线

- 本命令**只生成资料与清单**，不代提交、不承诺过审、不承诺"一键上架"。
- 隐私政策模板是通用条款框架，**不是法律意见**；正式发布前请找法务/合规确认。

## 执行流程

### 1. 加载知识

加载 skill `lhg-ma-store`（第 3-5 节）与 `lhg-ma-privacy`（第 3-4 节）。

### 2. 生成资料包（输出为 `store-kit/` 目录）

1. **商店文案** `listing.md`：应用名、副标题、应用描述（首屏 3 行钩子 + 功能分段）、关键词（按 lhg-ma-store 第 3 节公式）、分类与年龄分级建议。
2. **截图清单** `screenshots.md`：iOS / Android 各尺寸截图规格表、每张截图的文案与卖点分配（首图放核心价值）。
3. **隐私政策模板** `privacy-policy.md`：按 lhg-ma-privacy 第 4 节模板生成，标注""的占位项（公司名、联系邮箱、第三方 SDK 清单、数据保留期限）。
4. **审核避坑清单** `review-pitfalls.md`：常见被拒原因对照表（权限申请说明、内购合规、测试账号、元数据与实际功能一致），逐项自查打勾。
5. **提交前最终检查表** `final-check.md`：资料完整度逐项确认。

### 3. 完整度自查

跑审计脚本验证资料包完整度：
`python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/mobile_audit.py --target store-kit --format text`
blocker 清零后再交付给用户。

### 4. 交付说明

明确告诉用户三件事：
1. 资料包已备齐，但**提交动作需你亲手完成**（商店后台账号、签名证书都在你手里）。
2. 隐私政策模板需法务确认后再发布。
3. 被拒是常态：附上"被拒后 3 步"（读拒信→对号入座→改资料重提），不要慌。
